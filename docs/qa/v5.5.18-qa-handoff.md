## 1. Feature 一句话

把 ZStack 的 **KVM 主机** / **裸金属** / **容器节点** 三类硬件统一抽象成 `PhysicalServer`，支持统一的容量管理、硬件发现、电源管理、装机和角色注册。

### 5 个核心概念（QA 必懂）

| 概念 | 含义 |
|---|---|
| **PhysicalServer** | 一台物理机/裸金属/容器节点的统一模型 |
| **ServerPool** | PhysicalServer 池子，可关联多 Cluster |
| **ProvisionNetwork** | 装机网络（PXE/DHCP），可挂多个 ServerPool |
| **PhysicalServerRole** | PhysicalServer 在某角色下的注册（KVM_HOST / BAREMETAL_V2 / CONTAINER_HOST） |
| **装机 LongJob** | `APIProvisionPhysicalServerMsg` 装机异步任务，进度可查，MN 重启后可继续 |

### 这次发布动了什么（QA 重点测）

1. 新建 PhysicalServer 全家族 8 张表 + 容量真表
2. 27 个新 API（管理 PhysicalServer / ServerPool / ProvisionNetwork / 角色 / 装机 / 电源 / 硬件发现）
3. 三类硬件统一接入（KVM/BM2/Container）：path-1 先创建 PhysicalServer 再 attach 角色；path-2 老的 AddHost / AddChassis API 自动同步生成 PhysicalServer + 角色记录
4. 统一 Power API：以 OOB 凭据为先，无 OOB 直接报错（不像老 BM2 有自己的命令链）
5. 统一硬件发现：IPMI 和 agent 两条采集线汇成一份硬件信息
6. Container Cordon 熔断：容量低于安全阈值自动 cordon 节点，恢复后自动 uncordon
7. 装机异步任务：装机过程分阶段，MN 重启后可恢复进度

### 不在本 release scope（不要测）

- BM1（老裸金属）退场迁移
- 统一容量分配引擎（`AllocateServerMsg`）→ 推 v5.5.18.x patch release
- ESXi vcenter 半迁移
- KVM 装机端到端编排（PXE 装完后自动 register 成 KVM Host 一键流）→ v1.1+
- 自动 attach Host 一键编排 → v1.1+
- STANDALONE_PXE 非-gateway PXE → v1.1+
- 跨角色 serialNumber 归一化 → v1.1+
- 混部 4 个边界场景（cordon 阈值抖动 / K8s metrics race / K8s 删 node 同步延迟 / K8s label 篡改）→ 设计已知约束

### 3.9 调用模板

```bash
# zstack-cli — Create PhysicalServer
zstack-cli CreatePhysicalServer \
    name=server01 \
    zoneUuid=<zone-uuid> \
    poolUuid=<pool-uuid> \
    oobAddress=192.168.1.100 \
    oobUsername=admin \
    oobPassword=xxxxxx \
    serialNumber=ABC123

# REST — Attach KVM_HOST 角色
# (zstack-cli 当前不支持 roleConfig Map 参数，必须用 REST)
curl -X POST -H "Authorization: OAuth $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"params":{"serverUuid":"<uuid>","roleType":"KVM_HOST","roleConfig":{"username":"root","password":"xxx"}}}' \
  http://<mn-ip>:8080/zstack/v1/physical-servers/<uuid>/roles

# REST — Attach BAREMETAL_V2 角色（需 IPMI 凭据）
curl -X POST -H "Authorization: OAuth $TOKEN" -H "Content-Type: application/json" \
  -d '{"params":{"serverUuid":"<uuid>","roleType":"BAREMETAL_V2","clusterUuid":"<bm2-cluster>","roleConfig":{"chassisType":"ipmi","ipmiAddress":"192.168.1.100","ipmiUsername":"admin","ipmiPassword":"calvin"}}}' \
  http://<mn-ip>:8080/zstack/v1/physical-servers/<uuid>/roles

# REST — 装机异步任务
curl -X POST -H "Authorization: OAuth $TOKEN" -H "Content-Type: application/json" \
  -d '{"params":{"uuid":"<uuid>","provisionNetworkUuid":"<net>","imageUuid":"<image>"}}' \
  http://<mn-ip>:8080/zstack/v1/physical-servers/<uuid>/actions

# 查异步任务状态
zstack-cli QueryLongJob conditions="apiId=<job-id>"
```

### 3.10 测试后数据一致性核查（每个 P0 测试做一遍）

```sql
-- 1. 每个 PhysicalServer 必须有对应的容量记录
SELECT COUNT(*) FROM PhysicalServerVO ps
LEFT JOIN PhysicalServerCapacityVO psc ON psc.uuid = ps.uuid
WHERE psc.uuid IS NULL;
-- 期望: 0

-- 2. 每个角色记录的 roleUuid 必须能在 HostVO 找到
SELECT COUNT(*) FROM PhysicalServerRoleVO r
WHERE r.roleType IN ('KVM_HOST','BAREMETAL_V2','CONTAINER_HOST')
  AND NOT EXISTS (SELECT 1 FROM HostVO h WHERE h.uuid = r.roleUuid);
-- 期望: 0

-- 3. 同一 PhysicalServer 不能重复 attach 同种角色
SELECT serverUuid, roleType, COUNT(*) c FROM PhysicalServerRoleVO
GROUP BY serverUuid, roleType HAVING c > 1;
-- 期望: 空集

-- 4. 同 zone 下 serialNumber 必须唯一
SELECT zoneUuid, serialNumber, COUNT(*) c FROM PhysicalServerVO
WHERE serialNumber IS NOT NULL
GROUP BY zoneUuid, serialNumber HAVING c > 1;
-- 期望: 空集
```

## 9. 不要漏的 6 个细节

1. **`oobManagementType` 只接受 `ipmi`**。其他值（如 REDFISH）必须报错。`IPMI` 大小写不影响。
2. **24 个 PS API 全 admin-only**。普通账户调用必须 403。
3. **`oobPassword` 永远不出现在 API 返回**。QA 抓包必须确认。
4. **`roleConfig` 里的密码字段也不出现在日志**。Attach 时 `password` 字段不应进 management-server.log。
5. **MN 重启不丢装机进度**（AC-PN-15）— 装机中途 `systemctl restart zstack-mgmt` 后异步任务应自动恢复，不应重新 PXE。
6. **`zstack-cli` 不支持 `roleConfig` Map 参数** — Attach Role 必须用 REST curl（§3.9 模板）。
